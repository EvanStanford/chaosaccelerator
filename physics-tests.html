Not automated

  • Any editing control used while a run is playing/paused resets the scene to its pre-play state first, then applies that action - never requires a manual Reset first. This is a DOM/interaction-state behavior (see resetBeforeLockedControlAction and lockedDuringPlaybackControls in physics-ui.js), not a numeric one, so it doesn't fit this page's scene-in/scene-out style of test. Check by hand in #editor-view: let a run finish (or Pause it, or drag the progress slider mid-run), then click a tool, a sample, Clear All, or change a mapping/ simulation setting - confirm the scene visibly resets to what was authored before Play, and the action you just took (the new tool armed, the new sample loaded, the new setting applied) takes effect immediately, with no separate Reset click needed. Try it for a select/slider too (e.g. Edge Handling, Output property) and confirm the value you just picked is what's applied, not whatever it was before Play.
  • A paused-or-finished run freezes on its own frame, but Play (fresh), Reset, and Fractal-ize all still act on the true starting state. Playback writes each displayed frame straight into scene.bodies, so a run left where it stopped would otherwise make that moment look like the authored scene. initialScene is the fix: it's untouched by playback (only scene.bodies gets written to), so tick()'s completion branch can just pausePlayback() and leave the display frozen, while Fractal-ize calls resetToInitialScene() first - silently restoring the true start before it acts, without that restore itself being visible if the user was just looking at the frozen frame a moment before. (Reset already worked this way.) Check by hand after touching tick()/ resetToInitialScene()/togglePlayPause(): note a body's position, let a run finish, confirm the display stays on the final frame (not snapping back), then confirm Reset followed by a fresh Play replays from the noted starting position rather than from wherever the frozen run ended. Also drag the progress slider mid-run and confirm it pauses and scrubs to the dragged frame (holding on the real final frame if dragged past an early stop) without disturbing that same starting state.
